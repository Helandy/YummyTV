# Плеер Alloha: устройство и механика

Alloha — единственный балансер, который не отдаёт прямую ссылку на поток. Он отдаёт **живую
подписанную сессию**: набор анти-бот заголовков плюс master-URL с токеном в пути, у которого есть
TTL. Сессию нужно добыть, поддерживать живой и проксировать. Отсюда восемь файлов в
`feature/player/data/.../extractor/alloha/` вместо одного экстрактора на 150 строк, как у Kodik.

Документ описывает механизм целиком. Пункты с ⚠️ — инварианты: места, где «очевидная оптимизация»
ломает воспроизведение. Каждый подтверждён замерами на устройстве.

Референс для сверки: `~/AndroidStudioProjects/alloha-parser-kotlin`.

---

## 1. Общая схема

```
PlayerViewModel
  └─ PlayerStreamHandler.resolve()
       └─ OpenAllohaStreamSessionUseCase
            └─ DefaultPlayerStreamRepository.openAllohaSession()
                 ├─ AllohaPlaybackSessionManager.find(iframeUrl)   ← переиспользование живой сессии
                 └─ AllohaExtractor.openSession()
                      ├─ AllohaWebViewPool.acquire()               ← старт Chromium — самый дорогой шаг
                      ├─ wrapperHtml(iframeUrl) → loadDataWithBaseURL
                      │    └─ JS перехватывает XHR/fetch/WebSocket страницы
                      │         └─ AndroidBridge → onReady / onM3u8Refreshed / onConfigUpdate / …
                      ├─ parseSources(bnsi)                        ← озвучки, качества, субтитры
                      └─ LiveAllohaStreamSession                   ← состояние + ротация
                           └─ AllohaStreamProxy                    ← loopback HLS-прокси
                                                                      ↑
                                              Media3 играет отсюда: http://127.0.0.1:PORT/master.m3u8?token=…
```

Ключевая идея: **мы не воспроизводим поток сами и не даём воспроизводить его странице напрямую.**
Страница плеера живёт в скрытом WebView, её собственный сетевой стек перехватывается из JS, а
добытые URL и заголовки отдаются локальному прокси, через который уже играет Media3.

Зачем прокси вообще: CDN отдаёт сегменты только с анти-бот заголовками сессии. Media3 своих
заголовков туда не поставит (и они меняются при ротации), поэтому все URL в плейлисте переписываются
на loopback, а заголовки подставляет прокси.

## 3. Формат `bnsi`

Страница плеера запрашивает `…/bnsi/…` и получает JSON — это **источник правды** о том, какие
озвучки реально есть у серии (каталог сайта может врать).

```jsonc
{
  "hlsSource": [
    {
      "audioId": "10",            // идентификатор озвучки у Alloha
      "label": "(Russian) AniLibria",
      "default": true,
      "quality": {
        "1080": "https://cdn-a/…/master.m3u8 or https://cdn-b/…/master.m3u8",
        "720":  "…"
      }
    }
  ],
  "tracks": [
    { "kind": "captions", "label": "Русский", "language": "rus", "src": "//…/sub.vtt" }
  ]
}
```

Что делает `parseSources()`:

- `hlsSource[]` → список озвучек. Каждая со своей лестницей качеств.
- **`"url1 or url2"`** — у качества может быть два CDN через ` or `. Берётся **первый**; второй
  wrapper-JS использует как браузерный fallback при 403/500/503.
- Метки качеств нормализуются: `1080` → `1080p`, сортировка по числу в метке.
- `audioId` может отсутствовать — тогда id = индекс, чтобы дорожка осталась выбираемой.
- `//host/path` → `https://host/path` (`normalizeStreamUrl`).
- `tracks[]` с `kind == "captions"` → субтитры; формат берётся из расширения `src`.
- Пустой `hlsSource` или ноль качеств → `AllohaSourceUnavailableException` (у этой озвучки нет
  источника — не общая ошибка, а «выберите другую озвучку»).

## 4. Заголовки сессии

Копятся в JS из `setRequestHeader`/`fetch(init.headers)` самой страницы и синтезируются вручную.

| Заголовок                  | Откуда                                             | Роль                                                    |
|----------------------------|----------------------------------------------------|---------------------------------------------------------|
| `authorizations`           | `setRequestHeader` страницы                        | Токен на фильм. Стабилен в пределах сессии.             |
| `accepts-controls`         | `setRequestHeader`, обновляется из `config_update` | **edge_hash**. По нему CDN расшифровывает токен в пути. |
| `borth`                    | `setRequestHeader`                                 | Одноразовый nonce **на конкретный запрос**.             |
| `origin`, `referer`        | синтез из `w.location.origin`                      | Обязательны.                                            |
| `user-agent`               | из настроек WebView                                | Десктопный Chrome, стабилен на процесс.                 |
| `sec-fetch-dest/mode/site` | синтез                                             | Как у браузера.                                         |

**Что прокси НЕ пересылает** (`BLOCKED_FORWARD_HEADERS`): `host`, `connection`, `content-length`,
`transfer-encoding`, `accept-encoding` — ими владеет OkHttp; `cookie` — ставится отдельно из
`CookieManager`; `x-requested-with`, `content-type` — не нужны; **`borth`** — одноразовый, повтор
даёт периодический 403 `token_decrypt`.

⚠️ **Прокси обязан добавлять браузерные заголовки, которых хуки не видят.** Перехват ловит только
то, что страница ставит **явно**, а `Accept-Language` и client hints (`sec-ch-ua`, `-mobile`,
`-platform`) браузер добавляет сам. Без них CDN видит Chrome-UA без единого client hint — аномалия.
Показательный замер: запрос плеера из WebView на master проходил, а запрос прокси на **тот же URL**
получал 403 `client_blocked`. Сейчас они добавляются явно и выводятся из предъявляемого UA, чтобы
ему не противоречить (`DEFAULT_ACCEPT_LANGUAGE`, `CHROME_VERSION`, `platformHintFor`).

## 5. Добыча сессии

### 5.1 Загрузка обёртки

`loadDataWithBaseURL(baseUrl = "https://alloha.yani.tv/", wrapperHtml, …)`.

⚠️ **baseUrl обязан быть хостом Alloha.** Он делает страницу-обёртку same-origin с iframe — иначе
`iframe.contentWindow.document` недоступен и перехват невозможен в принципе.

⚠️ **`webView.getUrl()` возвращает `about:blank` — это нормально.** `getUrl()` отдаёт `historyUrl`,
пятый аргумент `loadDataWithBaseURL`, а мы передаём `null`. По нему **нельзя** диагностировать
«страницу затёрли»: так выглядит любая наша загрузка.

### 5.2 Установка хуков

⚠️ **Хуки ставятся опросом `contentWindow` каждые 20 мс, а не на `iframe.onload`.** К моменту `load`
скрипты страницы уже отработали и её запрос `/bnsi/` мог завершиться — хук его не увидит, извлечение
зависнет на весь таймаут, хотя плеер прекрасно играет. Замерено: страница грузилась **46 раз из
46**, а bnsi перехватывался лишь **в 8**. Опрос ограничен 8 секундами, останавливается после первой
успешной установки; `onload` остаётся страховкой и покрывает повторную навигацию.

⚠️ **Метка защиты от повторной установки — на самой обёрнутой функции**
(`w.XMLHttpRequest.prototype.open.__alloha`), не на объекте окна. Expando на window не удержался, и
опрос обернул хуки **526 раз** каскадом (каждая поверх предыдущей), полностью убив плеер. Свежий
документ после навигации всегда приносит нативный `open()` без метки — поэтому та же метка и
защищает от дублей, и корректно переустанавливает хуки после навигации.

Опрос пропускает окно с `location.href === 'about:blank'` — промежуточное состояние iframe до
перехода на реальный URL.

### 5.3 Что ставит обёртка

| Хук                                                          | Что делает                                                                                                                          |
|--------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| `XMLHttpRequest.prototype.open`                              | На `load`: ловит `/bnsi/` → `onReady`; ловит `master.m3u8` из `responseURL` → `onM3u8Refreshed`. `loadend` — запасной перехват URL. |
| `XMLHttpRequest.prototype.setRequestHeader`                  | Копит анти-бот заголовки.                                                                                                           |
| `fetch`                                                      | То же плюс браузерный fallback: при 403/500/503 повторяет на втором CDN из `"url1 or url2"`.                                        |
| `WebSocket`                                                  | `hookSocket()` читает `config_update` (edge_hash + ttl) и шлёт heartbeat `{type:'playing'}` раз в 25 с.                             |
| `Object.defineProperty(document,'visibilityState'/'hidden')` | Подделка видимости на обоих документах — WebView не прикреплён к окну.                                                              |
| Опрос 1500 мс                                                | Держит плеер играющим; жмёт кнопку play, **только если** на корне `.allplay` нет класса `allplay--playing`.                         |
| Скан текста                                                  | `/озвучка\s*недоступна/i` → `onDubbingUnavailable`.                                                                                 |

⚠️ **Запрос master у плеера НЕ блокируется.** Раньше блокировался — из посылки, что токен в пути
одноразовый и «кто первый взял, тот и выиграл». Посылка неверна: референс просто наблюдает запрос и
перезапрашивает **тот же самый URL** своим прокси — работает. А блокировка оставляла плеер страницы
без медиа (`readyState=0`, `currentTime` не двигался), из-за чего он рвал свой WebSocket через
~2.5 с, `config_update` не приходил никогда, и каждая ротация упиралась в 8-секундный таймаут.

⚠️ **`.allplay__play-btn` не существует** на текущей вёрстке — селектор от старой версии, клик по
нему был мёртвым кодом. Реальная кнопка: `button.allplay__controls__item.allplay__control`, в
играющем состоянии с `aria-label="Пауза"`. **Клик по ней во время воспроизведения ставит на паузу**,
поэтому он под условием отсутствия `allplay--playing` на корне.

### 5.4 Колбэки моста

`onReady(bnsi, headers)` · `onM3u8Refreshed(url, headers)` ·
`onConfigUpdate(edgeHash, ttl, headers)`
· `onStreamHeaders(headers)` · `onDubbingUnavailable()` · `onLog(message)`

### 5.5 Таймауты добычи

| Константа                | Значение | Смысл                                                                              |
|--------------------------|----------|------------------------------------------------------------------------------------|
| `NO_SIGNAL_TIMEOUT_MS`   | 10 с     | Не пришло **ничего** → перезагрузить обёртку. В норме bnsi приходит за 0.15–0.9 с. |
| `MAX_WRAPPER_RELOADS`    | 2        | Итого три попытки внутри общего потолка.                                           |
| `MASTER_WAIT_TIMEOUT_MS` | 6 с      | bnsi есть, подписанного master нет → отдать сессию на захваченном.                 |
| `TIMEOUT_MS`             | 30 с     | Общий потолок; дальше `Failed`.                                                    |

Сессия отдаётся, когда есть **и** разобранные источники, **и** подписанный master
(`deliverWhenReady`).

## 6. Жизнь сессии

`LiveAllohaStreamSession` хранит заголовки, master-URL, TTL и **`generation`** — счётчик, по
которому прокси понимает, что сессия сменилась.

**Расписание обновления** (`PlayerAllohaSessionHandler`): сон до
`expiresAt − SESSION_REFRESH_LEAD_MS`
(20 с), затем `refresh()`, затем ожидание нового TTL опросом каждые 500 мс до
`SESSION_ROTATION_WAIT_MS` (15 с).

**Ротация** (`refresh()`) перезагружает обёртку, а новые сигналы складывает в `staging`. Живое
состояние продолжает обслуживать запросы старым, ещё валидным токеном. Коммит атомарный — иначе
прокси половину окна работал бы на полуобновлённой сессии, что Media3 показывает как буферизацию.
Форсированный коммит — `STAGED_COMMIT_TIMEOUT_MS` (8 с).

⚠️ **`config_update` не приходит никогда.** Сокет страницы стабильно живёт ~2.5 с и закрывается с
`code=1005`, а heartbeat шлётся раз в 25 с и не успевает уйти ни разу. Причина **не** в отсутствии
медиа — проверено: даже когда плеер реально играет, сокет всё равно рвётся. Следствия:
`accepts-controls`
не ротируется, TTL всегда угаданный fallback 120 с. Поэтому есть флаг **`sawConfigUpdate`**: пока
такого сигнала не было ни разу, ожидания на него **не армятся** — ни `STAGED_COMMIT_TIMEOUT_MS`
(8 с на каждую ротацию), ни `HOST_CHANGE_CONFIG_WAIT_MS` (10 с при смене хоста CDN). До этого флага
все ротации до единой упирались в таймаут.

⚠️ **`selectAudioTrack()` перезаписывает `masterUrl` значением из `masterFor()` — сырым bnsi-URL.**
Вызов до старта воспроизведения затирает правильно подписанный master и даёт 403 `token_decrypt` на
части CDN. Поэтому восстановление сохранённой дорожки живёт в `PlayerViewModel` (после старта), а не
в `PlayerStreamHandler` (до публикации URL).

**Переиспользование**: `AllohaPlaybackSessionManager.find(iframeUrl)` отдаёт живую сессию, а
`release(immediately = false)` откладывает закрытие на `CONFIGURATION_CHANGE_GRACE_MS` (10 с) —
чтобы поворот экрана или быстрый перезаход не пересоздавали WebView.

## 7. Прокси

### URL, которые он выдаёт

```
http://127.0.0.1:PORT/master.m3u8?token=<uuid>[&audio=<id>][&quality=<label>]
http://127.0.0.1:PORT/proxy?url=<base64url>&token=<uuid>
```

`token` — секрет на сессию: loopback-порты не изолированы между приложениями одного пользователя.
Выбор озвучки и качества едут **в URL**, поэтому переключение — это просто подмена MediaItem на той
же живой сессии.

⚠️ **Бинд строго на IPv4-loopback** (`InetAddress.getByName("127.0.0.1")`). `getLoopbackAddress()`
на устройстве с предпочтением IPv6 возвращает `::1`, и тогда на `127.0.0.1`, куда указывают все
выдаваемые URL, не слушает никто — Media3 получает `ConnectException` на каждый запрос. Проверяется
так: `cat /proc/net/tcp6` покажет LISTEN, а `/proc/net/tcp` будет пуст.

⚠️ **Никакого резолва имён на пути запроса.** `404` можно отдавать только на заведомо кривой запрос:
он входит в `FATAL_RESPONSE_CODES` (`400, 401, 403, 404, 410`) в `PlayerLoadErrorHandlingPolicy`,
Media3 его **не ретраит вовсе** и сразу валит воспроизведение. Всё сетевое обязано проходить через
`fetchWithRecovery` и возвращаться ретраибельным `503`.

### Обработка запроса

1. Разбор query одним проходом, сверка `token`.
2. `/master.m3u8` → `masterProvider(audio, quality)`; иначе base64-декод `url=`.
3. Плейлист → `servePlaylist` → переписывание всех URL на loopback; сегмент → `serveSegment`.
4. Кэш сегментов `CACHE_CAPACITY = 4`, префетч `PREFETCH_COUNT = 2`, дедупликация одновременных
   запросов через `computeIfAbsent`. Range-запросы кэш обходят.

### Лестница восстановления

| Шаг | Что делает                                                                                        |
|-----|---------------------------------------------------------------------------------------------------|
| 1   | Точный повтор запроса на свежем соединении при 403 (`Connection: close`, `evictAll`)              |
| 2   | Перезапись пути под текущий master (`rewriteToCurrentPath`) — для сегментов от прошлого поколения |
| 3   | Эскалация к `refresh()` сессии, single-flight                                                     |
| 4   | Удержание запроса до `SEGMENT_HOLD_FOR_REFRESH_MS` (14 с) и повтор на новом поколении             |
| 5   | Для `-a1.ts`/`-a2.ts` — отдать пустой 188-байтовый TS-пакет; для прочих — 503                     |

Маркеры отказа в `X-VD`: `session_blocked`, `token_decrypt`, `client_blocked`. При `token_decrypt`
удержание **пропускается** — `refresh()` перезагружает тот же WebView и возвращает тот же edge_hash,
то есть это гарантированно бесполезный столл; лучше сразу эскалировать к свежей сессии.

⚠️ **`onSessionRotated` пересобирает `OkHttpClient` и `ConnectionPool`, а не просто зовёт
`evictAll()`.** Evict закрывает только простаивающие соединения; занятое в момент eviction вернётся
в тот же пул и достанется новой сессии. Подмена пула — единственный способ развести соединения
разных сессий. Кэш сегментов и запросы в полёте при этом **сохраняются** — они авторизованы прошлым
токеном и валидны, а их сброс Media3 показал бы как стоп прямо на ротации.

## 8. Полная лестница отказа

Кто за что отвечает, снизу вверх:

| Уровень   | Владелец                      | Что делает                                                                    |
|-----------|-------------------------------|-------------------------------------------------------------------------------|
| Сегмент   | `AllohaStreamProxy`           | ретрай 403 → rewrite пути → hold 14 с → 503                                   |
| Сессия    | `LiveAllohaStreamSession`     | `refresh()`, staged-коммит, ожидание ≤ 20 с                                   |
| Поток     | `PlayerViewModel`             | `startAllohaPlaybackRecovery` → свежая сессия, задержка 1 с                   |
| Попытки   | `PlayerAllohaRecoveryHandler` | `MAX_ATTEMPTS = 4`, дальше — ошибка с действиями                              |
| Подсказка | `PlayerViewModel`             | через `ALLOHA_RECOVERY_HINT_DELAY_MS` (15 с) предложить сменить плеер/озвучку |

Для не-Alloha источников работает другой путь: `PlayerPlaybackRetryHandler` с `MAX_ATTEMPTS = 3` и
«тихий» реконнект под буфер (`SILENT_RETRY_COUNT = 20` в `PlayerLoadErrorHandlingPolicy`), который
для Alloha намеренно **выключен** — у неё своё восстановление.

## 9. Загрузки

Оффлайн-путь идёт **через тот же прокси**, что и воспроизведение, но со своей сессией.

`AllohaDownloadStrategy.openLiveSession()` открывает сессию с `reusePlaybackSession = false` — то
есть отдельную от той, на которой сейчас играет плеер, чтобы фоновая загрузка и просмотр не мешали
друг другу. TTL fallback короче: 55 с против 120 с у воспроизведения.

`VideoDownloadWorker` берёт `liveSession.initialStream.url` — это **loopback-URL прокси**, — и
передаёт **пустые заголовки** (`downloadHeaders = emptyMap()`), потому что заголовки сессии
подставляет сам прокси. Воркер держит таймер обновления сессии и закрывает её в конце.

`decorateHeaders(originOverride = "https://alloha.yani.tv")` применяется только там, где живой
сессии нет — то есть для не-HLS (прогрессивных) файлов, которые качаются напрямую.

Ключи кэша — `RotatingHlsCacheKeyFactory`: манифест намеренно перечитывается на каждой ротации (его
URL эфемерный), а медиасегменты кладутся под стабильное имя файла с префиксом загрузки, чтобы
пережить смену подписи. Не путать: `LiveAllohaStreamSession.directStream` (прямые CDN-URL без
прокси) к загрузкам отношения не имеет — он используется только в `AllohaExtractor.extract()`,
разовом пути резолва.

⚠️ Панель/таб дорожек Alloha показывается **только когда источник действительно Alloha**
(`usesAlloha && alloha.hasAudioChoice`). Раньше был фолбэк на встроенные в поток дорожки
(`trackSelection`), из-за чего таб с подписью «Alloha» (строка `player_mobile_audio_track` — это
буквально «Alloha») появлялся и для Kodik-потоков, если в них были выбираемые дорожки. См.
`TvExoPlayerView` и `MobileNativePlayer`.

Списки дорожек Alloha чистятся в `PlayerSourceStreamHandler.preparingStreamLoad` /
`preparingStreamResolve`, чтобы не пережить смену источника. Ветка `preserveCurrentStream = true`
их намеренно сохраняет — это восстановление той же самой сессии на месте.

## 11. Отладка

Логи идут через `AnalyticsTracker.log` — в дебаге logcat, в релизе теги `AllohaExtractor` и
`AllohaStreamProxy` (список — `PersistedLogTags`) пишутся прямо в файл логов приложения (Настройки →
О приложении → Поделиться логами, если включена «Настройки → Общие → Запись логов»); остальные теги
в релизе no-op. Ссылки в таких строках усекаются
до хоста (`AppLogDiagnosticSink`). Подробные логи прокси по запросам (`verbose`) в релизе
по-прежнему выключены.

```bash
adb shell setprop log.tag.AllohaExtractor DEBUG
adb shell setprop log.tag.AllohaStreamProxy DEBUG
```

| Маркер                            | Значение                                                                                              |
|-----------------------------------|-------------------------------------------------------------------------------------------------------|
| `bnsi audioTracks=[…]`            | Источники разобраны.                                                                                  |
| `master refreshed`                | Пойман подписанный master.                                                                            |
| `ready headers=…`                 | Сессия собрана; в строке — поколение, host, ttl и отпечатки заголовков.                               |
| `Proxy started port=…`            | Готово, дальше играет Media3.                                                                         |
| `WebSocket hooked`                | Страница открыла сокет. ⚠️ **Не** индикатор того, что JS запустился — вызывается из `hookSocket()`.   |
| `no signal after 10000ms`         | Обёртка ничего не отдала, идёт перезагрузка.                                                          |
| `session timed out after 30000ms` | Провал добычи; `streamReady`/`refreshedMaster` показывают, чего не хватило.                           |
| `staged session commit timed out` | Ротация не собралась за 8 с; `ready/master/config` — что именно не пришло.                            |
| `CDN failure code=403 xVd=…`      | `client_blocked` → заголовки; `token_decrypt` → master протух; `session_blocked` → сессия отвергнута. |
| `outgoing …`                      | Точный набор заголовков, ушедших на CDN (только под `verbose`).                                       |

⚠️ **Про измерения.** CDN режет клиента по объёму открытых сессий: после нескольких десятков
запусков подряд с одного IP начинают сыпаться `client_blocked`/`session_blocked`, и любая статистика
после этого меряет блокировку, а не код. Между сериями нужны паузы, а прогоны с ненулевым
`blocked=`/`tokdec=` — отбрасывать. Разброс частоты отказов между сериями на одном и том же коде
доходил до 42–100%, так что выводы по 10–12 прогонам ненадёжны.
