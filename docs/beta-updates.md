# Бета-канал обновлений

Приложение само проверяет обновления через GitHub Releases (`Helandy/YummyTV`). Пользователь может
включить в «Общих» настройках переключатель «Бета-версии», тогда ему предлагаются и pre-release
сборки. По умолчанию выключен. Проверка идёт при запуске (`MainSideEffectsHandler.checkForUpdates`),
поэтому новое значение действует со следующего запуска.

## Нумерация и публикация

Стабильные версии — три числа (`1.21.1`, `1.21.2`). Беты получают четвёртое число — порядковый номер
беты после последней стабильной:

```
v1.21.1 → b1.21.1.1 → b1.21.1.2 → … → b1.21.1.37 → v1.21.2 → b1.21.2.1 → …
```

Бет между стабильными может быть сколько угодно, третье число при этом не растёт.

|                        | Стабильный релиз   | Бета               |
|------------------------|--------------------|--------------------|
| `yummytv.versionName`  | `1.21.1`           | `1.21.1.2-beta`    |
| Тег на GitHub          | `v1.21.1`          | `b1.21.1.2`        |
| «Set as a pre-release» | нет                | да                 |
| `yummytv.versionCode`  | больше предыдущего | больше предыдущего |

Правила:

- Суффикс ровно `-beta`, без цифры: `1.21.1.2-beta`, а не `1.21.1-beta2`. Проверка минимальной
  версии (`FeatureToggleVersionSupportChecker`) выкидывает из версии нецифровые символы, и `-beta2`
  стал бы лишним сегментом.
- Первые три числа беты совпадают с последней стабильной. Бета `b1.21.2.1`, выпущенная до `v1.21.2`,
  окажется новее будущей стабильной `1.21.2`, и бета-тестеры её не получат.
- `versionCode` только растёт, и между бетами, и между бетой и стабильной. Android не ставит APK с
  меньшим `versionCode` поверх установленного, обновление упадёт на установке.
- Бета — любой релиз с флагом pre-release или с тегом на `b`. Ставить лучше оба признака: флаг ещё и
  помечает релиз на странице GitHub.

## Сравнение версий

Единственный компаратор — `compareVersions` / `isVersionNewer` в
`feature/update/domain/.../util/VersionComparator.kt`:

1. Числовые части сравниваются слева направо как числа, в любом количестве. Недостающая часть —
   ноль, поэтому `1.21.1` = `1.21.1.0`.
2. При равных числах стабильная версия новее беты. Нужно только для старой схемы с тремя числами
   (`1.21.2-beta` < `1.21.2`).

Порядок: `1.21.1` < `1.21.1.1-beta` < `1.21.1.2-beta` < `1.21.1.10-beta` < `1.21.2`.

Версию релиза `GitHubReleaseMapper` берёт из тега без префикса `v`/`b`. Для беты добавляется
`-beta`, чтобы совпасть с `versionName` установленной беты: `b1.21.1.2` → `1.21.1.2-beta`.

## Какой релиз предлагается

1. Загружается список релизов; черновики и релизы без APK отбрасываются.
2. Если «Бета-версии» выключены, отбрасываются и беты.
3. Из оставшихся выбирается релиз с самой большой версией (не первый в ответе GitHub).
4. Диалог показывается, только если версия строго новее установленной. Для беты заголовок «Вышла
   новая бета-версия 1.21.1.2».
5. Счётчик «пропущено N обновлений» считает все релизы из п. 2, новее установленной версии.

| Установлено      | «Бета-версии» | Лучший релиз на GitHub | Результат                                          |
|------------------|---------------|------------------------|----------------------------------------------------|
| `1.21.1`         | выкл          | `v1.21.1`, `b1.21.1.3` | Ничего: беты скрыты, стабильная уже стоит          |
| `1.21.1`         | вкл           | `v1.21.1`, `b1.21.1.3` | Бета `1.21.1.3`                                    |
| `1.21.1.2-beta`  | вкл           | `b1.21.1.3`            | Бета `1.21.1.3`                                    |
| `1.21.1.2-beta`  | вкл           | `b1.21.1.3`, `v1.21.2` | Стабильная `1.21.2`: она новее всех бет `1.21.1.N` |
| `1.21.1.2-beta`  | выкл          | `v1.21.1`              | Ничего: `1.21.1` старше беты, ждать `v1.21.2`      |
| `1.21.1.2-beta`  | выкл          | `v1.21.2`              | Стабильная `1.21.2`, это уводит с беты             |
| `1.21.1.37-beta` | выкл/вкл      | `v1.21.2`              | `1.21.2`: номер беты значения не имеет             |

Откатиться с беты на более старую стабильную нельзя. Если выключить бету, пользователь остаётся на
своей версии и получает следующую стабильную. Ручной откат возможен только через удаление приложения
(Android не поставит APK с меньшим `versionCode`), при этом пропадают локальные данные.

## Обязательное обновление

Минимальную версию задаёт feature toggle. Если установленная версия ниже, диалог обязательный,
независимо от переключателя. Беты с четырьмя числами сравниваются корректно: `1.21.1.2-beta` →
`1.21.1.2`, выше `1.21.1` и ниже `1.21.2`.

## Ограничения

- Запрашивается одна страница `/releases?per_page=100`: последние 100 релизов, включая беты. Если
  после стабильной версии выйдет больше 100 бет, пользователи стабильного канала её не увидят, а
  счётчик пропущенных обновлений не считает релизы старше этой сотни.
- Проверка есть только при запуске, кнопки «проверить сейчас» в настройках нет.
