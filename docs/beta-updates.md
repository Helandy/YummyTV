# Бета-канал обновлений

Приложение само проверяет обновления через GitHub Releases (`Helandy/YummyTV`). Пользователь может
включить в «Общих» настройках переключатель **«Бета-версии»**. Тогда ему предлагаются не только
стабильные релизы, но и pre-release сборки. По умолчанию переключатель выключен.

Проверка идёт при запуске приложения (`MainSideEffectsHandler.checkForUpdates`), поэтому новое
значение переключателя действует со следующего запуска.

## Как нумеровать

Стабильные версии — три числа: `1.21.1`, `1.21.2`. Беты получают **четвёртое число — порядковый
номер
беты после последней стабильной**:

```
v1.21.1  →  b1.21.1.1  →  b1.21.1.2  →  …  →  b1.21.1.37  →  v1.21.2  →  b1.21.2.1  → …
```

Бет между двумя стабильными версиями может быть сколько угодно, а третье число при этом не растёт.
Следующая стабильная `1.21.2` новее любой беты `1.21.1.N`, поэтому бета-тестер переходит на неё
обычным обновлением.

## Как публиковать

|                        | Стабильный релиз   | Бета               |
|------------------------|--------------------|--------------------|
| `yummytv.versionName`  | `1.21.1`           | `1.21.1.2-beta`    |
| Тег на GitHub          | `v1.21.1`          | `b1.21.1.2`        |
| «Set as a pre-release» | нет                | **да**             |
| `yummytv.versionCode`  | больше предыдущего | больше предыдущего |

Правила:

* **Суффикс пишется ровно `-beta`, без цифры**, то есть `1.21.1.2-beta`, а не `1.21.1-beta2`. Номер
  беты задаёт четвёртое число. Проверка минимальной поддерживаемой версии
  (`FeatureToggleVersionSupportChecker`) выкидывает из версии все нецифровые символы, так что
  `-beta2` превратился бы в лишний сегмент.
* **Первое, второе и третье числа беты совпадают с последней стабильной.** После `v1.21.1` идут
  `b1.21.1.1`, `b1.21.1.2`… Если выпустить бету как `b1.21.2.1` до выхода `v1.21.2`, она окажется
  новее будущей стабильной `1.21.2`, и бета-тестеры не получат эту стабильную.
* **`versionCode` только растёт**, и между бетами, и между бетой и стабильной версией. Android не
  ставит APK с меньшим `versionCode` поверх установленного, и обновление упадёт уже на установке.
* Приложение считает бетой любой релиз, у которого стоит флаг pre-release **или** тег начинается
  с `b`. Ставить лучше оба признака: флаг заодно помечает релиз на самой странице GitHub.

## Как сравниваются версии

Единственный компаратор: `compareVersions` / `isVersionNewer` в
`feature/update/domain/.../util/VersionComparator.kt`.

1. Сначала сравниваются числовые части слева направо, **как числа**, а не как строки, и в любом
   количестве. Недостающая часть считается нулём, поэтому `1.21.1` = `1.21.1.0`.
2. Если числа равны, стабильная версия новее беты. Это важно только для старой схемы с тремя
   числами (`1.21.2-beta` < `1.21.2`). При четырёх числах такой пары не бывает.

Отсюда порядок: `1.21.1` < `1.21.1.1-beta` < `1.21.1.2-beta` < `1.21.1.10-beta` < `1.21.2`.

Версию релиза маппер (`GitHubReleaseMapper`) берёт из тега без префикса `v`/`b`. Если релиз бета,
к версии добавляется `-beta`, чтобы она совпадала с `versionName` установленной беты:
`b1.21.1.2` → `1.21.1.2-beta`.

## Какой релиз предлагается

1. Приложение загружает список релизов. Черновики и релизы без APK отбрасываются.
2. Если «Бета-версии» выключены, отбрасываются и все беты.
3. Из оставшихся выбирается релиз с **самой большой версией** (не первый в ответе GitHub).
4. Диалог показывается, только если эта версия **строго новее** установленной `versionName`.
   Для беты в заголовке пишется «Вышла новая бета-версия 1.21.1.2».
5. Счётчик «пропущено N обновлений» считает все релизы из п. 2, которые новее установленной версии.

## Типовые ситуации

| Установлено      | «Бета-версии» | Лучший релиз на GitHub | Результат                                                    |
|------------------|---------------|------------------------|--------------------------------------------------------------|
| `1.21.1`         | выкл          | `v1.21.1`, `b1.21.1.3` | ничего: беты скрыты, а стабильная уже стоит                  |
| `1.21.1`         | вкл           | `v1.21.1`, `b1.21.1.3` | предложит бету `1.21.1.3`                                    |
| `1.21.1.2-beta`  | вкл           | `b1.21.1.3`            | предложит бету `1.21.1.3`                                    |
| `1.21.1.2-beta`  | вкл           | `b1.21.1.3`, `v1.21.2` | предложит стабильную `1.21.2`: она новее всех бет `1.21.1.N` |
| `1.21.1.2-beta`  | выкл          | `v1.21.1`              | **ничего**: `1.21.1` старше беты. Человек ждёт `v1.21.2`     |
| `1.21.1.2-beta`  | выкл          | `v1.21.2`              | предложит стабильную `1.21.2` и тем самым уведёт с беты      |
| `1.21.1.37-beta` | выкл/вкл      | `v1.21.2`              | предложит `1.21.2`: номер беты значения не имеет             |

Главное: **откатиться с беты на более старую стабильную версию нельзя**. Если выключить бету,
пользователь остаётся на своей версии и получит ближайшую следующую стабильную. При схеме с
четырьмя числами это просто следующий стабильный релиз. Откат вручную возможен только через
удаление приложения: Android не даст поставить APK с меньшим `versionCode`, а при удалении
пропадут локальные данные.

## Обязательное обновление

Минимальную поддерживаемую версию задаёт feature toggle. Если установленная версия ниже неё,
диалог показывается как обязательный, независимо от переключателя. Беты с четырьмя числами
сравниваются там корректно: `1.21.1.2-beta` → `1.21.1.2`, это выше `1.21.1` и ниже `1.21.2`.

## Ограничения

* Запрашивается одна страница `/releases?per_page=100`: это последние 100 релизов, включая беты.
  Если после стабильной версии выйдет больше 100 бет, пользователи стабильного канала её не увидят.
  Кроме того, счётчик пропущенных обновлений не считает релизы старше этой сотни.
* Проверка есть только при запуске. Кнопки «проверить сейчас» в настройках нет.
