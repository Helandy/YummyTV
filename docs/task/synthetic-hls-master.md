# Синтетический HLS master: что сделано и что осталось

Коммит `24530ce84` (19.11.2026). Задача: убрать лоадер и обрыв буфера при смене качества и ускорить
возврат вверх при росте скорости. Раньше у источников «отдельная ссылка на качество» смена качества
перезапускала media item (`setMediaItem` + `prepare`), а оценка полосы ExoPlayer при полном буфере
протухала, поэтому повышение шло 15–35 с.

## Что сделано

- Из ссылок по качествам собирается синтетический master (`data:application/x-mpegURL;base64,…`,
  `PlayerSyntheticMasterUtils.kt`). Подходят источники из `PER_QUALITY_HLS_PATTERNS` — сейчас Kodik и
  AniLibria. ExoPlayer переключает варианты сам: общий буфер, смена на границе сегмента, свежая
  оценка полосы на каждом сегменте.
- Адаптивный режим: выбранное качество — потолок высоты (`setMaxVideoSize`). Ручной выбор закрепляет
  вариант (min = max). Поток не пересоздаётся: `playbackUrl` в `PlayerPlaybackUiStateMapper` один и
  тот же, меняются `videoHeightCap` и `videoHeightPinned`.
- Повышение лимита адаптивного качества поднимает потолок сразу (`raiseMasterCeiling` в
  `PlayerViewModel`), а не после ожидания политики адаптации (было ~30 с).
- На время master выключается `forceHighestSupportedBitrate`. `data:`-URI обслуживает
  `SchemeRoutingDataSource` мимо кэша и сети. Cast получает реальную ссылку лучшего качества
  (`YummyTvCastMediaItemConverter`).
- Загрузки, офлайн, локальные файлы, ручной выбор для остальных источников работают как раньше:
  мастер — только для воспроизведения, `qualities` и `qualityHeaders` не менялись.

Проверено на телефонном эмуляторе (Kodik): master загружается без ошибок, понижение при просадке
сети, возврат на 720p через ~10 с после восстановления, смена лимита и ручное закрепление меняют
разрешение за доли секунды без перезапуска кодека. Старая политика адаптации
(`QualityAdaptationPolicy`) работает как регулятор потолка.

Проверено на TV-эмуляторе `Television_4K` (Kodik, Re:Zero 4, серия 2): старт на 480p, ABR поднялся
до 720p через ~13 с без лоадера, дропов кадров нет. **Ручной выбор качества (закрепление min = max)
сбрасывает буфер:** после выбора 480p буфер ушёл в 0 и на 1–2 с вернулся лоадер, потом буфер снова
набрался. Адаптивное переключение (ABR и подъём лимита) буфер не сбрасывает. Идея: для ручного выбора
пробовать только потолок без нижней границы (`min`) и сравнить, сбрасывается ли буфер; но тогда
ABR может играть ниже выбранного качества.

Эксперимент «только потолок» проведён (19.11.2026): буфер сбрасывается так же (0 с, лоадер 1–2 с),
плюс на секунду показывается промежуточное 360p, прежде чем встать на 480p. Значит, сброс вызывает
сама смена параметров выбора дорожек, когда уже буферизованный вариант перестаёт быть допустимым.
Подъём потолка (текущий вариант остаётся допустимым) и ABR буфер не сбрасывают. Закрепление min = max
оставлено: оно хотя бы сразу встаёт на выбранное качество. Ручное понижение качества — единственный
случай с коротким лоадером; убрать его целиком можно только скрытием индикатора, пока буфер
восстанавливается быстро (решение по UI, не по плееру).

## Осталось

1. **Реальная приставка.** TV-эмулятор пройден (см. выше); осталось проверить на железе: падение
   качества при дропе кадров, ABR не выше потолка. Программный декодер эмулятора сам роняет кадры.
2. ~~Другие HLS-источники~~ — проверены по живым плейлистам (19.11.2026) и добавлены в
   `PER_QUALITY_HLS_PATTERNS`: AiLiberty, Sameband, StudioMir. У каждого отдельный media-плейлист на
   качество без `EXT-X-MEDIA`, в сегментах `h264 + aac` (проверено `ffprobe` на сегментах),
   суммарная длительность у качеств совпадает, PTS сегмента = накопленная длительность + одинаковое
   смещение (~1,48 с) у всех качеств, то есть временная шкала согласована. Границы сегментов у
   качеств не везде совпадают (у AniLibria 96 из 491, у AiLiberty 44–55 из 139, у Sameband и StudioMir
   тоже), но ExoPlayer переключает варианты по времени, это допустимо. Не проверено на устройстве:
   глюки на стыке при реальном переключении. **Anistar не проверен:** сайт за Cloudflare, плейлист
   без приложения не достать; в список не добавлен. Проверять через отладку в приложении
   (`…/360.mp4/index.m3u8`, нужен Referer зеркала).
3. ~~Тест на `raiseMasterCeiling`~~ — сделан в `PlayerViewModelTest`.
4. **Упростить `QualityAdaptationPolicy`** для master-источников: проба при протухшей оценке и часть
   интервалов им не нужны, политика только держит потолок. Делать после приставки, чтобы не убрать
   защиту слабых устройств.

## Как проверять на эмуляторе

- Ограничение сети эмулятора работает только на мобильных данных: `adb shell svc wifi disable`,
  `adb shell svc data enable`, затем `adb emu network speed 900` (снять — `speed full`).
- Смену разрешения видно по логу: `adb logcat | grep "Rect crop"` (`1279x719` = 720p, `639x359` = 360p),
  перевыделение кодека — по строкам `CCodec`.
- Оверлей диагностики (буфер, разрешение, дропы) включается в «Настройки → Общие → Запись логов».
