# Все плееры на общий HLS master: статус по источникам

Продолжение [synthetic-hls-master.md](synthetic-hls-master.md). Цель: смена и возврат качества без
перезапуска потока и без лоадера, с общим буфером. Это возможно только там, где поток HLS (или DASH):
у прямых mp4-файлов общего буфера нет. Здесь список всех источников: что уже переведено, что можно
перевести и что нельзя.

## Уже переведено (синтетический master из ссылок по качествам)

Для источников, у которых каждое качество — отдельный media-плейлист. Master собирает
`PlayerSyntheticMasterUtils.kt` (`PER_QUALITY_HLS_PATTERNS`), плеер получает его `data:`-URI. Все
проверены по живым плейлистам (аудио вшито в сегменты, нет `EXT-X-MEDIA`, PTS согласован).

| Источник | Шаблон ссылки | Проверено |
|---|---|---|
| Kodik | `…/<N>.mp4:hls:manifest.m3u8` | плейлисты, эмулятор (телефон и ТВ) |
| AniLibria | `…/videos/media/ts/<релиз>/<серия>/<N>/<hash>.m3u8` | плейлисты, эмулятор |
| AiLiberty | `ailiberty.top/video/playlists/<токен>.m3u8` | плейлисты |
| Sameband | `sameband.studio/v/anime/…/index.m3u8` | плейлисты, эмулятор |
| StudioMir | `…/animes/vids/encoded/…/hls/<N>/<hash>_<N>.m3u8` | плейлисты |
| Anistar | `an-media.org/video/<hash>/<N>.mp4/index.m3u8` | плейлисты, эмулятор |

## Можно перевести: у источника уже есть настоящий master

Сейчас приложение разбирает такой master на отдельные ссылки по качествам, и смена качества
пересоздаёт поток. Задача: отдавать плееру сам master (ExoPlayer сам выбирает вариант) и ограничивать
высоту так же, как у синтетического (`videoHeightCap` / `videoHeightPinned`), а `qualities` оставить
для выбора качества, загрузок и Cast.

Общий план:

1. В `PlayerStreamResolveResult.Stream` добавить `adaptiveMasterUrl: String?` (+ заголовки, если
   отличаются). Экстрактор заполняет его, когда проверил, что master безопасен для ExoPlayer.
2. `PlayerPlaybackUiStateMapper`: если есть `adaptiveMasterUrl`, он идёт в `playbackUrl`, а выбранное
   качество — потолок или закрепление (как для синтетического master). Остальное уже работает:
   `PlayerMediaItemUpdater`, `PlayerQualityAdaptationEffect(deviceOnly)`, `raiseMasterCeiling`.
3. По каждому источнику проверить (команды — в разделе «Как проверять» ниже): есть ли `EXT-X-MEDIA`
   (отдельные аудиодорожки не должны потеряться), нужны ли особые заголовки (`Referer`, `User-Agent`),
   срок жизни подписи, что ExoPlayer не требует `forceHighestSupportedBitrate`.

| Источник | Что известно | Особенности |
|---|---|---|
| CVH | `hlsUrl` из `/api/v1/player/sv/video/<id>`: настоящий master, 6 вариантов (144p–1080p) с реальными `BANDWIDTH`, аудио вшито, у 480p/720p/1080p сетка сегментов совпадает. Проверено вручную 19.11.2026. | Сегменты в проверенном ответе относительные, на том же хосте `vdNNN.okcdn.ru`; в [cvh-player.md](../cvh-player.md) написано про сырые IP сегментов, перепроверить. `OkCdnFailoverInterceptor` надо научить пары хостов HLS. Ключ кэша HLS и mp4 (`type=2`) различается только путём. Загрузки остаются на mp4. Нужен браузерный `User-Agent`. |
| Aniboom | Настоящий master (`hlsUrl`), аудио отдельной группой `EXT-X-MEDIA`. Сейчас качество = фрагмент `#yummy-max-height=N` в ссылке. | Смена фрагмента меняет URL, элемент пересоздаётся. Достаточно использовать `videoHeightCap` без фрагмента. |
| Ashdi, Fenix, Moon, Mikai | Источники отдают master, экстрактор режет его на ссылки по качествам. | Проверить аудиогруппы и заголовки. Fenix всегда отдаёт master. |
| Dreamerscast, Anidub, Animebesst, Animeon | То же. У Anidub нужен `User-Agent`. | Проверить по живым плейлистам. |
| Rutube | `buildQualityMap` режет master, при неудаче `auto`. | Проверить, что отдельное аудио не теряется. |
| Amedia | Есть `hlsByQuality` и `masterUrl`. | Использовать `masterUrl`, если он настоящий. |

## Отдельный разбор: Alloha

У Alloha на каждое качество своя ссылка `master.m3u8`, а лесенка отдельная на каждую озвучку. Живая
сессия (WebSocket, `edge_hash`, `/events`, `/stat`), `PlayerDataSourceFactory` на каждом запросе
подставляет свежий `edge_hash` и считает номер сегмента и байты. Сервер блокирует клиента при
нарушении (`session_blocked`, `client_blocked`). Из нескольких `master.m3u8` можно собрать общий
master, но порядок запросов меняется, и последствий для блокировки неизвестно. Делать только после
отдельной проверки на живой сессии, см. [alloha-player.md](../alloha-player.md).

## Нельзя: прямые файлы или чужой формат

| Источник | Причина |
|---|---|
| Aksor, Animevost, Anime4k, Sibnet | прямой mp4 на качество, сегментов нет |
| VK | mp4 на качество; HLS и `hls_fmp4` уже идут как `auto` без выбора качества |
| Zedfilm | DASH / mp4 / m3u8, качество определяется по тексту ссылки; для DASH нужен отдельный путь |
| Torrent | поток идёт через TorrServer, смена качества не относится |

## Как проверять источник

- Master/плейлист: `curl` с теми же заголовками, что у экстрактора; смотреть теги (`EXT-X-MEDIA`,
  `EXT-X-STREAM-INF`), число и длительности сегментов у разных качеств.
- Аудио и таймлайн: скачать сегмент и `ffprobe -show_entries stream=codec_type,start_time`;
  PTS сегмента должен равняться накопленной длительности плюс одно и то же смещение у всех качеств.
- Эмулятор: ограничение сети только на мобильных данных (`svc wifi disable`, `svc data enable`,
  `adb emu network speed 900`); смена разрешения видна по `logcat | grep "Rect crop"`; оверлей
  диагностики — «Настройки → Общие → Запись логов».

## Известные ограничения подхода

- Ручное понижение качества сбрасывает буфер (1–2 с лоадера): ExoPlayer сбрасывает буфер, когда
  загруженный вариант перестаёт быть допустимым. Адаптивное переключение и подъём потолка буфер не
  сбрасывают.
- Номинальные `BANDWIDTH` синтетического master (`nominalBitrateBps`) завышены относительно реальных
  битрейтов некоторых источников, поэтому ABR может держаться ниже возможного. У настоящих master
  (CVH, Aniboom и т. д.) значения реальные.
