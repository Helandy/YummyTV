# Восстановление входа через Block Store

После переустановки приложения или переезда на новое устройство (перенос данных с телефона,
восстановление из облачной копии Google) пользователь остаётся залогиненным в Yani — вводить логин
и пароль заново не нужно. Работает и на телефоне, и на ТВ, если на устройстве есть Google Play
Services.

## Зачем отдельное хранилище

Refresh-токен хранится в `SecureYaniAuthPreferences` и зашифрован ключом Keystore конкретного
устройства. Поэтому он намеренно исключён из Auto Backup (`app/src/main/res/xml/backup_rules.xml`,
`data_extraction_rules.xml`): на другом устройстве его всё равно не расшифровать.

[Google Block Store](https://developer.android.com/identity/block-store) хранит небольшие данные
приложения внутри Google Play Services, отдельно от его собственных данных. Они переживают
переустановку и очистку данных, а при переносе устройства или восстановлении из облака (с E2E-
шифрованием, если стоит блокировка экрана) попадают на новое устройство. Backup-правила при этом не
меняются.

Block Store — не синхронизация: на уже установленных устройствах запись видна только локально, на
другие она попадает лишь в момент переноса или восстановления.

## Шифрование

В Block Store токен кладётся как есть, без нашего шифрования. Ключ Keystore привязан к устройству:
зашифрованный им токен на новом устройстве было бы нечем расшифровать. Защиту обеспечивает сам
Google Play Services:

| Где лежит токен                            | Чем защищён                                                                                                                    |
|--------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------|
| Локально, в хранилище Google Play Services | Песочница Android и шифрование диска. Запись читает только наше приложение с той же подписью, другим приложениям она не видна. |
| Облачная копия в аккаунте Google           | End-to-end шифрование ключом из PIN-кода, графического ключа или пароля блокировки экрана. У Google этого ключа нет.           |
| Прямой перенос устройство → устройство     | Зашифрованный канал между устройствами.                                                                                        |

Без блокировки экрана end-to-end шифрование недоступно, и Block Store не отправляет данные в облако
даже при `setShouldBackupToCloud(true)`. Токен переедет только при прямом переносе; незашифрованная
копия в облако не попадает.

Локальная копия внутри Google Play Services защищена примерно как наш режим
`TokenStorageMode.FALLBACK`: песочницей, а не Keystore. Без root или взлома устройства её не
прочитать. Для refresh-токена, который отзывается выходом из аккаунта, это приемлемо.

Если понадобится строже:

- писать в Block Store только при `isEndToEndEncryptionAvailable() == true` — пользователи без
  блокировки экрана лишатся восстановления входа совсем, даже при прямом переносе;
- выставить `setShouldBackupToCloud(false)` — вход восстановится только при прямом переносе и после
  переустановки на том же устройстве.

## Как устроено

Одна запись с ключом `yani_refresh_token`, `setShouldBackupToCloud(true)`.

| Когда                                            | Что делаем                 | Где                                              |
|--------------------------------------------------|----------------------------|--------------------------------------------------|
| Вход (пароль, QR/NSD, подтверждение регистрации) | `save(token)` после успеха | `YaniAccountRepository.signInWithTokenInternal`  |
| Обновление токена                                | `save(token)`              | `YaniAccountRepository.refreshToken`             |
| Смена пароля                                     | `save(token)`              | `YaniProfileSettingsRepository.changePassword`   |
| Явный выход                                      | `clear()`                  | `YaniAccountRepository.logout`                   |
| Старт главного экрана без сессии                 | `restore()` → вход         | `MainViewModel` → `RestoreAccountSessionUseCase` |

Токен пишется при каждом изменении: сервер может ротировать его на refresh, и в Block Store должен
лежать актуальный.

Файлы:

- `feature/account/data/.../data/account/backup/AuthTokenBackup.kt` — контракт data-слоя;
- `feature/account/data/.../data/account/backup/BlockStoreAuthTokenBackup.kt` — реализация;
- `feature/account/domain/.../usecase/RestoreAccountSessionUseCase.kt`;
- `feature/main/presentation/.../handler/MainSideEffectsHandler.kt` — `restoreAccountIfMissing()`.

## Восстановление

`AccountRepository.restoreSessionFromBackup()`:

1. Если сессия уже есть — ничего не делает.
2. Достаёт токен из Block Store; нет записи — выходит.
3. Прогоняет токен через тот же атомарный `signInWithTokenInternal`, что и обычный вход: сначала
   `GET /profile` с этим токеном, потом запись токена, профиля и настроек, при ошибке — откат.
4. Успех — событие аналитики `account_session_restored_from_backup`. UI отдельно не уведомляется:
   `observeAccountSession()` сам переключит экраны в авторизованное состояние.

Вызывается перед `refreshAccountIfStale()`, так что восстановленный токен сразу попадает под
обычную логику обновления.

## Когда запись удаляется

Только в двух случаях:

- **явный выход** из аккаунта — иначе при следующем запуске вход бы «воскрес»;
- **сервер отверг токен** (`401`/`403` на `GET /profile`) — чтобы не долбиться с ним на каждом
  старте.

Сетевые ошибки запись не трогают — попробуем при следующем запуске. Не удаляем её и при откате
неудачного входа, и когда чтение из Keystore вернуло пусто: на кастомных прошивках Keystore бывает
ненадёжен (см. `TokenStorageMode.FALLBACK`), и бэкап — как раз страховка на этот случай.

## Без Google Play Services

Все вызовы Block Store best-effort: на приставках без GMS `Task` падает, ошибка пишется в
`AnalyticsTracker.log` (тег `AuthTokenBackup`) и глотается. Вход, выход и обновление токена
работают как раньше, просто без бэкапа.

## Ограничения

- Восстановленное устройство использует ту же серверную сессию, что и старое (тот же
  refresh-токен). Если yani при refresh инвалидирует прежний токен, одно из устройств
  разлогинится. Для сценария «переезд» это приемлемо.
- Без блокировки экрана облачной копии нет — см. [Шифрование](#шифрование).

## Как проверить

Нужен эмулятор или устройство с Google Play Services.

1. Войти в аккаунт → в logcat нет ошибок с тегом `AuthTokenBackup`.
2. `adb shell pm clear su.afk.yummy.tv.debug` → запустить → вход восстановлен без экрана логина.
3. Выйти из аккаунта → `pm clear` → запустить → входа нет (запись удалена).
4. Устройство без GMS: вход и выход работают, в logcat только пойманные ошибки `AuthTokenBackup`.
