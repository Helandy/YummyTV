# Подписки на озвучку/балансер

Как устроена подписка на новые серии в yani. Главное: **состояние подписки отдаёт сам сервер в
списке
видео тайтла** — восстанавливать его по названиям озвучек из списка подписок не нужно и невозможно.

Подписка живёт на тройке «тайтл + балансер + озвучка». В приложении она видна в двух местах:

* экран подписок тайтла (`DetailsSubscriptionsDestination` → `SubscriptionsViewModel`) и
  оверлей-пикер
  в деталях на ТВ — там подписку **переключают**;
* экран «Мои подписки» (`MySubscriptionsDestination` → `MySubscriptionsViewModel`) — там подписки
  **перечисляют** по всем тайтлам.

Это два разных источника данных, и они не взаимозаменяемы.

## Контракт API

### `GET /anime/{id}/videos`

Плоский список: **одна запись = серия × озвучка × балансер**.

```json
{
    "video_id": 1027521,
    "number": "1",
    "data": {
        "player": "Плеер Kodik",
        "dubbing": "Озвучка РуАниме / DEEP",
        "player_id": 4
    },
    "watched": {
        "end_time": 1336,
        "date": 1784061705
    },
    "subscribed": true,
    "iframe_url": "…"
}
```

* `player_id` стабилен: `2` Alloha, `3` CVH, `4` Kodik, `7` Sibnet, `8` VK. **У озвучки
  идентификатора
  нет — только название.**
* **`subscribed`** — подписан ли пользователь на новые серии этой озвучки и балансера. Поле приходит
  только авторизованному пользователю (в публичном ответе его нет вовсе), стоит у всех серий группы
  и
  является единственным достоверным источником состояния. Рядом с ним живёт такой же
  пользовательский
  `watched`.
* `number` (номер серии) — строка, местами с ведущим нулём; для подписок он не нужен, но
  используется
  при выборе «последней» серии группы.

### `PUT | DELETE /video/{video_id}/subscribe`

Тела запроса нет, ответ — `{"response": true}`. `video_id` — любая серия нужной озвучки: сервер сам
сводит её к тройке «тайтл + балансер + озвучка». Официальный веб-клиент шлёт `video_id` серии,
открытой в плеере.

Проверено вживую: две подписки на разные озвучки одного балансера дают **две** записи, `DELETE`
удаляет ровно одну. Приложение отписывается тем видео, у которого сервер сам проставил `subscribed`.

### `GET /users/{userId}/lists/subs`

```json
{
    "sub": {
        "dubbing": "",
        "player": "Kodik",
        "player_id": 4
    },
    "anime_id": 26429,
    "anime_url": "tabakoshka",
    "title": "…",
    "poster": {
        …
    }
}
```

Список всех подписок пользователя — по строке на подписку. Используется **только** экраном
«Мои подписки» (первый пункт вкладки уведомлений). Для состояния конкретной озвучки не годится:

* **`sub.dubbing` не сообщает озвучку подписки.** Приходит либо пустым, либо `null`, либо
  перечислением всех озвучек этого балансера — `"AniLibria() AniDUB() SHIZA Project() … "` —
  одинаковым у всех подписок одного балансера. Из-за `null` в non-null поле с дефолтом разбор ответа
  падал целиком, пока в `YaniApiJson` не включили `coerceInputValues` (регресс закрыт
  `YaniSubscriptionsParsingTest`).
* `sub.player` — короткое имя (`"Kodik"`), тогда как в списке видео оно приходит как
  `"Плеер Kodik"`.
* `video_id` и номера серии в ответе нет вовсе — отписаться по строке этого списка нельзя, только
  перейти в тайтл.
* `anime_id` и `player_id` приходят то числом, то строкой — отсюда `JsonElement` в DTO.

## Ключи

`SubscriptionKeys` (модуль `feature/account/domain`) — единственное место, где считаются ключи:

* `playerKey` — `id:<player_id>`, если он есть; иначе `name:<нормализованное имя>` со снятым
  префиксом «Плеер »/«player », потому что в двух ответах имя приходит по-разному.
* `dubbingKey` — нормализованное название озвучки (trim, lowercase, `ё` → `е`, только буквы и
  цифры).
* `subscriptionKey = playerKey|dubbingKey` — ключ строки на экране подписок тайтла.
* `animePlayerKey = animeId|playerKey` — ключ строки в «Моих подписках». Озвучки в нём нет
  намеренно:
  список её не сообщает.

## Экран подписок тайтла

1. `DetailsSubscriptionHandler` (`@Singleton`, общий для деталей и экрана подписок) грузит детали и
   видео тайтла. Неавторизованный пользователь получает `SignedOut` и пустой список.
2. `List<AnimeVideo>.toSubscriptionOptions()` отбрасывает видео без `id` и без названия озвучки,
   группирует остальные по `subscriptionKey` и на каждую группу собирает `SubscriptionOption`:
    * `episodesCount` — число видео в группе;
    * `subscriptionVideoId` — id видео, которому сервер сам проставил `subscribed`, иначе последняя
      серия группы (по номеру, при равенстве — по `id`). Отписываться безопаснее именно подписанным
      видео;
    * `isSubscribed` — `pendingStates[key]`, иначе `videos.any { it.isSubscribed }`.
3. Порядок: озвучки сортируются по суммарным просмотрам (`views` всех их видео на всех балансерах),
   внутри одной озвучки балансеры — тоже по просмотрам, при равенстве по имени плеера. Так сверху
   оказывается то, что реально смотрят.
4. Переключение (`SubscriptionToggled`) оптимистично в два слоя:
    * ViewModel сразу правит `isSubscribed` в своём состоянии — кнопка реагирует без задержки;
    * `DetailsSubscriptionHandler.pendingStatesByAnimeId` держит то же значение на время мутации,
      чтобы промежуточный пересчёт `toSubscriptionOptions` (например, перезагрузка видео) не вернул
      старую галочку. Запись удаляется в `finally`.
5. После успешного `PUT|DELETE` ждём `SUBSCRIPTION_REFRESH_DELAY` (350 мс) — серверу нужно время,
   чтобы мутация попала в ответ, — и вызываем `RefreshAnimeVideosUseCase`: кэш видео живёт 5 минут,
   и
   без принудительного перезапроса галочка вернулась бы в прежнее состояние.
6. Если запрос вернул `false` или упал, ViewModel откатывает галочку, а
   `AccountMutationErrorNotifier` (через `SetVideoSubscriptionUseCase`) показывает ошибку мутации.
7. При выходе из аккаунта кэш видео помечается устаревшим (`AnimeStorage.expireAllVideos()`) —
   `watched` и `subscribed` в нём принадлежат прежнему пользователю.

## Экран «Мои подписки»

1. `GetVideoSubscriptionsUseCase` схлопывает ответ через `distinctBy(animePlayerKey)`: подписки на
   разные озвучки одного балансера приходят несколькими записями, неотличимыми для UI, и без этого
   строка дублировалась бы.
2. `YaniVideoSubscriptionRepository` держит список в offline-first кэше на пользователя и язык с TTL
   5 минут (`ACCOUNT_SHORT_TTL_MS`). Переключение подписки сбрасывает кэш
   (`deleteVideoSubscriptions`), поэтому вернувшись из тайтла пользователь видит актуальный список.
3. `ScreenShown` перечитывает список при каждом показе экрана, но лоадер показывает только на пустом
   списке — из тайтла возвращаются к уже отрисованным строкам.
4. В строке показываются только тайтл, постер и балансер: озвучки в ответе нет. Клик ведёт в детали
   тайтла, где подписками уже можно управлять.

## Чего делать не надо

Сравнивать `sub.dubbing` из `/lists/subs` с названиями озвучек из `/videos` — в любом виде, включая
«мягкое» сравнение по вхождению подстроки. Именно так и было сделано раньше: перечисление всех
озвучек балансера подходило под каждую строку списка, и подписка на одну озвучку подсвечивала весь
балансер. На реальных данных вхождение подстроки ломается и само по себе: «Субтитры» ⊂
«Субтитры Wakanim», «Озвучка AniDUB» ⊂ «Озвучка AniDUB Online», «Озвучка Kansai» ⊂
«Озвучка KANSAI Studio».

Хранить выбранную озвучку локально тоже не нужно: такая таблица знала бы только о подписках,
оформленных в этом приложении, и не видела бы сделанных на сайте или до её появления.
