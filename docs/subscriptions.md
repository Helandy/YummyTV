# Подписки на озвучку и балансер

Подписка в yani живёт на тройке «тайтл + балансер + озвучка». Состояние подписки отдаёт сам сервер в
списке видео тайтла: восстанавливать его по названиям озвучек из списка подписок нельзя и не нужно.

В приложении подписки видны в двух местах, у них разные источники данных:

- экран подписок тайтла (`DetailsSubscriptionsDestination` → `SubscriptionsViewModel`) и
  оверлей-пикер в деталях на ТВ: подписку переключают;
- «Мои подписки» (`MySubscriptionsDestination` → `MySubscriptionsViewModel`): подписки по всем
  тайтлам перечисляют.

## Контракт API

### `GET /anime/{id}/videos`

Плоский список: одна запись — серия × озвучка × балансер.

```json
{
    "video_id": 1027521,
    "number": "1",
    "data": {
        "player": "Плеер Kodik",
        "dubbing": "Озвучка РуАниме / DEEP",
        "player_id": 4
    },
    "watched": {
        "end_time": 1336,
        "date": 1784061705
    },
    "subscribed": true,
    "iframe_url": "…"
}
```

- `player_id` стабилен: `2` Alloha, `3` CVH, `4` Kodik, `7` Sibnet, `8` VK. У озвучки идентификатора
  нет, только название.
- `subscribed` — подписан ли пользователь на новые серии этой озвучки и балансера. Приходит только
  авторизованному (в публичном ответе поля нет), стоит у всех серий группы и является единственным
  достоверным источником состояния. Рядом такой же пользовательский `watched`.
- `number` — строка, местами с ведущим нулём; нужна только при выборе «последней» серии группы.

### `PUT | DELETE /video/{video_id}/subscribe`

Тела нет, ответ `{"response": true}`. `video_id` — любая серия нужной озвучки, сервер сам сводит её
к тройке. Веб-клиент шлёт `video_id` серии, открытой в плеере.

Проверено вживую: две подписки на разные озвучки одного балансера дают две записи, `DELETE` удаляет
ровно одну. Приложение отписывается тем видео, у которого сервер сам проставил `subscribed`.

### `GET /users/{userId}/lists/subs`

```json
{
    "sub": {
        "dubbing": "",
        "player": "Kodik",
        "player_id": 4
    },
    "anime_id": 26429,
    "anime_url": "tabakoshka",
    "title": "…",
    "poster": {
        …
    }
}
```

Список всех подписок пользователя, по строке на подписку. Используется только экраном «Мои подписки»
(первый пункт вкладки уведомлений). Для состояния конкретной озвучки не годится:

- `sub.dubbing` озвучку подписки не сообщает. Приходит пустым, `null` или перечислением всех озвучек
  балансера (`"AniLibria() AniDUB() SHIZA Project() … "`), одинаковым у всех подписок балансера.
  Из-за
  `null` в non-null поле с дефолтом разбор падал целиком, пока в `YaniApiJson` не включили
  `coerceInputValues` (регресс закрыт `YaniSubscriptionsParsingTest`).
- `sub.player` — короткое имя (`"Kodik"`), в списке видео — `"Плеер Kodik"`.
- `video_id` и номера серии нет: отписаться по строке этого списка нельзя, только перейти в тайтл.
- `anime_id` и `player_id` приходят то числом, то строкой (`JsonElement` в DTO).

Нельзя сравнивать `sub.dubbing` с названиями озвучек из `/videos`, в том числе «мягко», по вхождению
подстроки. Перечисление всех озвучек балансера подходит под каждую строку, и подписка на одну
озвучку подсвечивает весь балансер. Вхождение подстроки ломается и само по себе: «Субтитры» ⊂
«Субтитры Wakanim», «Озвучка AniDUB» ⊂ «Озвучка AniDUB Online», «Озвучка Kansai» ⊂ «Озвучка KANSAI
Studio».

Хранить выбранную озвучку локально тоже не нужно: такая таблица знала бы только о подписках из этого
приложения и не видела бы сделанных на сайте.

## Ключи

`SubscriptionKeys` (`feature/account/domain`) — единственное место, где считаются ключи:

- `playerKey` — `id:<player_id>`, если он есть; иначе `name:<нормализованное имя>` без префикса
  «Плеер »/«player » (в двух ответах имя приходит по-разному).
- `dubbingKey` — нормализованное название озвучки (trim, lowercase, `ё` → `е`, только буквы и
  цифры).
- `subscriptionKey = playerKey|dubbingKey` — ключ строки на экране подписок тайтла.
- `animePlayerKey = animeId|playerKey` — ключ строки в «Моих подписках». Озвучки в нём нет, потому
  что список её не сообщает.

## Экран подписок тайтла

1. `DetailsSubscriptionHandler` (`@Singleton`, общий для деталей и экрана подписок) грузит детали и
   видео тайтла. Неавторизованный получает `SignedOut` и пустой список.
2. `List<AnimeVideo>.toSubscriptionOptions()` отбрасывает видео без `id` и без названия озвучки,
   группирует по `subscriptionKey` и собирает `SubscriptionOption`:
    - `episodesCount` — число видео в группе;
    - `subscriptionVideoId` — id видео с серверным `subscribed`, иначе последняя серия группы (по
      номеру, при равенстве по `id`). Отписываться безопаснее подписанным видео;
    - `isSubscribed` — `pendingStates[key]`, иначе `videos.any { it.isSubscribed }`.
3. Порядок: озвучки по суммарным просмотрам (`views` всех видео на всех балансерах), внутри озвучки
   балансеры по просмотрам, при равенстве по имени плеера.
4. Переключение (`SubscriptionToggled`) оптимистично в два слоя: ViewModel сразу правит
   `isSubscribed` в состоянии, а `DetailsSubscriptionHandler.pendingStatesByAnimeId` держит значение
   на время мутации, чтобы промежуточный пересчёт `toSubscriptionOptions` не вернул старую галочку.
   Запись удаляется в `finally`.
5. После успешного `PUT|DELETE` ждём `SUBSCRIPTION_REFRESH_DELAY` (350 мс), пока мутация попадёт в
   ответ, и зовём `RefreshAnimeVideosUseCase`: кэш видео живёт 5 минут, без перезапроса галочка
   вернулась бы.
6. Если запрос вернул `false` или упал, ViewModel откатывает галочку, а
   `AccountMutationErrorNotifier`
   (через `SetVideoSubscriptionUseCase`) показывает ошибку.
7. При выходе из аккаунта кэш видео помечается устаревшим (`AnimeStorage.expireAllVideos()`):
   `watched` и `subscribed` в нём принадлежат прежнему пользователю.

## Экран «Мои подписки»

1. `GetVideoSubscriptionsUseCase` схлопывает ответ через `distinctBy(animePlayerKey)`: подписки на
   разные озвучки одного балансера приходят несколькими неотличимыми для UI записями.
2. `YaniVideoSubscriptionRepository` держит список в offline-first кэше на пользователя и язык с TTL
   5 минут (`ACCOUNT_SHORT_TTL_MS`). Переключение подписки сбрасывает кэш
   (`deleteVideoSubscriptions`).
3. `ScreenShown` перечитывает список при каждом показе, лоадер только на пустом списке.
4. В строке только тайтл, постер и балансер. Клик ведёт в детали тайтла, где подписками уже можно
   управлять.
